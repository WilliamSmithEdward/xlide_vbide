Patch release for a security fix in the editor page, and the analyzer moves to v11.2.1.

- The editor page carries DOMPurify 3.4.17, which fixes GHSA-cg2g-xh64-v4q7, GHSA-mrv2-3pqr-j5jr and GHSA-c6gr-qvv4-5v3f. Earlier releases shipped the copy bundled inside the code editor component, 3.4.15, although the dependency audit reported the fix for an earlier advisory as in place. DOMPurify cleans the formatted text the editor shows, such as hovers.
- Ships analyzer v11.2.1. It reports more of what the VBE refuses, so code that showed no problems before can show some now:
  - A declaration that takes a name the module's host class already has, such as `Public Sub Save()` in ThisWorkbook or `Public Sub Delete()` in a sheet module (`member-exists-in-base-class`).
  - A Dim bound a Long cannot hold (`array-bound-overflow`).
  - A `#If` condition of `Nothing` (`nothing-directive-condition`), and a string `#If` condition VBA cannot convert.
- It also stops reporting code that Excel compiles or runs. Among those are a Type passed to a function inside `Debug.Print`, and `Resume 0`.
- A project that references Outlook's object library gets Outlook's types and members in completion and hover. Without the reference, code that names Outlook's types is reported as missing a library reference.
