## The theme: what has no observability is where the defects live

Three defects this session lived in surfaces nothing could report on, and that is not a
coincidence. Each was found by eye, and each is now readable through a route.

**The title bar reverted to the editor's own name.** Pressing Reset a second time changes no
execution state and rewrites the caption. The refresh had a guard that returned early when the
mode, workbook and module all matched what it last wrote, which compares our record of the
caption against our record of the caption; what it has to notice is the host rewriting the window
underneath us, which changes neither. Three polls ran in that state and each one went home.
`state.frameCaption` reads the window now.

**The console could not report the page failing to load.** The ring was installed at page ready,
so a bundle that throws while its modules initialise never created it, and the one route built
for that question answered `{"installed": false}`. It lives in `boot.js` now, ahead of the bundle,
and pushes the error to the host over `chrome.webview` rather than waiting to be asked.

**A workbook row was wider than its own pane.** Content-box plus its own padding, so the last ten
pixels, where a right-aligned control sits, hung into the tree's horizontal scroll. The plus
button was there and could not be seen.

## The bar is gone

Ten native menus become one wrench at the head of the toolbar, holding the five dialogs that are
genuinely the editor's own. Nothing was dropped without a home first, which is this table's
standing rule:

| Menu | Where its items went |
| --- | --- |
| File | Save and Import/Export already had homes. **Remove did not**, so it is on the module's row in the tree |
| Run | Run, Break, Reset were buttons. Design Mode is one now |
| Insert | Module, Class, UserForm are the plus on each workbook row |
| Help | About xlide is on the toolbar; native F1 goes deliberately |
| Tools | Options and Additional Controls go; the rest is the wrench |

**Two things genuinely left**, recorded rather than discovered later: Insert's Add Procedure
dialog, and Require Variable Declaration from the native Options dialog, which is what puts
`Option Explicit` at the top of a new module. The second has no equivalent in xlide's settings and
belongs there.

**How two menus are addressed as one.** Items are addressed by position chain and nothing else, so
a synthetic menu needs synthetic positions that lead back to real ones. A child of the wrench is
`rank * 1000 + realPosition`, translated before anything is walked: arithmetic, not a remembered
table, so nothing can go stale between the read that produced a path and the execute that uses it.

## Read this before trusting a green check

**My instruments were wrong more often than the product was, again.** Every one of these produced
a confident wrong reading:

- polling `dialogs` after driving a menu item, when the api's own guard cancels those dialogs
  within a couple of seconds by design. An empty list read exactly like an item that never ran.
  `dialogs` carries `recentlyCleared` now, because an instrument that alters what it measures has
  to say so in its own answer
- reading a CSS opacity in the same tick as the focus that changes it, which reports the value the
  transition is coming FROM
- a dead-code scan that reported 125 dead exports including `EditorBridge`, because its word
  boundaries were eaten between bash and node. Both scans now check themselves against three
  known-live names and print the result
- a doctor finding that spent the entire budget of the route it was added to: a three second page
  read inside a route with a three second deadline

**When a check goes red here, suspect the instrument first.** What settles it every time is
printing the numbers the check is judging.

## Open, in the order I would take them

1. **A module nothing references can be renamed once, and the second rename is refused.**
   Reproducible, and not what it first looks like.

   ```
   add Lonely, give it text, wait for a pass
   rename Lonely -> LonelyA     ok: 0 mention(s) in 0 module(s)
   rename LonelyA -> LonelyB    refused: 'LonelyA' is not a module of this workbook
   ```

   The refusal is the engine's, from `dispatcher.ts`, which checks the name against what the
   project was SEEDED with rather than against the assembly. So the rename landed in the object
   model and the engine never learned the new name.

   Three things it is NOT, each measured: not document-specific, though that is where it was
   found (`ThisWorkbook` and `Sheet1` both rename correctly, and their code names are renameable,
   which is the `(Name)` property and a different thing from a sheet's display name); not a
   debounce, since it still refuses fourteen seconds later; and not a missing re-analysis, since
   the log shows a pass at the next generation two milliseconds after the rename.

   What clears it is any edit that changes a module's TEXT, which is why a rename with mentions
   to replace never shows it: replacing them is the text change. The suspect is therefore the
   seeding skip, which compares sources, against a rename that changes a name and no source.

2. **The gate's `engine executable is current` step** compares against a checkout that moves. Make
   packaging the gate's first action rather than something it asserts afterwards.
2. **Require Variable Declaration** in the settings dialog, before somebody misses it.
3. **Two Excel instances against one export folder.** Files are written atomically, so nothing
   reads a half-written module, but there is no per-folder lock as xlide_vscode has.
4. **The native pane's rendering is unobserved.** Parity compares text, so a pane that draws wrong
   while holding the right text passes every check there is. I have no instrument for it I would
   trust, which is why it is written down rather than half-built.
5. **`AddInSession.cs` is 7,741 lines**, twice the next file. Split once already; there is no
   second seam that is not arbitrary, so leave it until one presents itself.
