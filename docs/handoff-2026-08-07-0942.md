## 2. Open, in the order I would take them

### 2a. Peek Definition jumps instead of peeking

The one thing left broken, and it is a **regression from this session**, not a pre-existing gap.

`provideDefinition` navigates through the host when the target is in another module, because the
standalone editor cannot open a model it is not showing. That fixed cross-module Go to Definition
— and broke Peek, because both commands go through the same provider. A provider that moves the
caret is answering a question by acting on it, which is the wrong shape and was the wrong fix.

The right seam is `monaco.editor.registerEditorOpener`, which the editor offers for exactly this.
**It was tried and it did not work**: with the opener registered and the provider pure, neither
peek nor reveal navigated at all — two broken things instead of one. That attempt was reverted
(the revert is the working tree at `df53272`; the attempt itself is not committed).

The current state is a deliberate choice: cross-module reveal WORKS, peek JUMPS. A broken jump
was judged worse than a peek that jumps. That is reversible if the judgement is wrong.

**What the next attempt needs**, and what makes it different from the last two: read
`StandaloneCodeEditorService.openCodeEditor` in
`ui/editor/node_modules/monaco-editor/esm/vs/editor/standalone/browser/standaloneServices.js`
and find what it checks before consulting registered openers. Both failed attempts guessed at
wiring. Neither read that function.

### 2b. Go to Definition on the declaration does nothing

Invoked where the caret is already at the definition, the editor runs its alternative definition
command. That defaulted to peeking references — which showed **3** references where xlide's list
shows **4**, the missing one being in a module with no tab. It is now pointed at
`xlide.showReferences` instead.

The command works when invoked by that id, and the option holds that id, but the fallback never
fires — so today the answer is that nothing happens. Better than a window showing three of four,
and not what was intended.

### 2c. The rename ambiguity report is over-broad

`renameFor` returns an `ambiguous` list of uses it deliberately did not touch. It currently
includes the OTHER procedure's own declaration and its own calls, which are a different symbol
and not something a developer needs to decide about. Only the genuinely ambiguous bare call
belongs there. Nothing displays this list yet, so nothing is wrong on screen — but it is not fit
to show as it stands.

### 2d. Smaller, stated rather than hidden

- **Rename cannot be undone.** The edit spans modules; the editor's undo stack is per model.
- **Rename resolves against the shown workbook.** With two open, renaming from the explorer in
  the one not shown is untried.
- **The loader spinner** occasionally appears during a resize. Ruled out: page reload (one
  overlay, one `ready`, `surfaceReady` true, nothing recreated). Not reproduced, so not fixed.
  The one path that would produce it without a reload is `HideLoader` returning early when
  `_handle == 0`, leaving `_loading` true forever. Unproven.
- **The diagnostic cascade** — one bad procedure header produces both `invalid-identifier-start`
  and a consequent `unmatched-block-closer`. This is in the SHARED analyzer, so xlide_vscode
  shows the same pair; fixing it here alone would make the two products disagree. The seam is
  `analyzeVbaModuleSource` in `xlide_vscode/src/vbaModuleAnalysis.ts`, which already filters at
  that point for transient-expression and suppression-directive cases.

## 3. What this session cost to learn

Recorded because each of these was paid for once and should not be paid for twice.

### The engine that runs is not the engine that was built

The add-in launches `engine\dist\xlide-engine.exe`. `npm run build` writes only `engine.cjs`,
which nothing at runtime reads. Four new operations were built, smoke-tested, committed and
published while the executable answering the add-in was hours old and refused every one as
"Unknown method". Three features were reported as verified and were not.

Nothing caught it: the engine smoke test runs against the bundle, and the gate did not build the
engine at all. It surfaced from a live session's log. `tools\verify.ps1` now fails when any engine
source is newer than the executable.

### Editor registrations cover less than their names

Five now, all found the same way — the provider registers cleanly and is then asked nothing,
which looks exactly like a provider that answers nothing:

| Feature | What its register module leaves out |
| --- | --- |
| `suggest` | the controller |
| `semanticTokens` | the whole-document contribution (it imports only the viewport one) |
| `gotoSymbol` | F12, Shift+F12, the peek windows, and their menu entries |
| `codeAction` | complete, but registers via `registerAction2`, so `getAction` returns null |
| references peek | `StandaloneReferencesController`, in a module nothing imports |

The way to tell a missing registration from a broken provider is to watch a running editor and
see whether the request goes out at all. Two neighbouring facts: a code-action provider must pass
`providedCodeActionKinds` as the third argument or the editor gates Ctrl+. off, and
`semanticHighlighting.enabled` must be set outright because `StandaloneTheme` hardcodes that flag
off and no standalone theme can say yes.

### The variable nobody varied

Twice, in the same shape.

**Rename** was probed only from the DECLARATION. Asked from a call site, the member resolver
answers with every module declaring that name, and the rename went through all of them —
renaming a `BrokenModule.RunTotal` that shared nothing but a name. Fixed by anchoring every
rename at the declaration whichever site it was asked from, so the entry point that was already
correct is the only one there is. The smoke test now pins it as a property: a rename from a call
site and one from the declaration must reach the same modules.

**Go to Definition** was tested only where the definition was in the SAME module. That path works
and looked correct. Crossing modules — the entire point of the feature — was never tried until
the developer tried it.

### Measuring beats the plausible hypothesis

Three times the obvious suspect was innocent and cost time:

- Resize lag looked like WebView2's compositor resizing a surface. It cost **0 ms across 191
  calls** — the browser side already skips unchanged bounds. The real cost was a cheap-looking
  refresh running 21 times per size step.
- Right-edge flicker looked like `CS_HREDRAW | CS_VREDRAW`. That flag is the existing
  *mitigation*; removing it would have shown the old native editor instead of a flat band.
- "Excel's window resize is our fault" — `MainWindowHandle` on that process is the **VBE frame**,
  not Excel's. Targeting `XLMAIN` explicitly showed **zero** refreshes and zero placements.

### What the preview harness cannot test

The browser pane does not composite frames, so anything needing a rendering lifecycle silently
does nothing there: screenshots, `ResizeObserver` (a fresh one fires **zero** times, not even its
initial callback), smooth scrolling, and zone widgets. A plain DOM modal renders fine — which is
part of why xlide's own references list is testable where the editor's peek window is not.

## 4. The test fixture

```bash
tools\New-RenameFixture.ps1
```

Writes `artifacts\fixtures\RenameFixture.xlsm` (gitignored, rebuilt on demand). Nine modules,
each labelled in its own comments with what to try and what must NOT move. `Consumer` is left
CLOSED and `Watcher` OPEN deliberately — the module with no tab is the one that gets silently
missed, and the two are reached by different code paths.

It found a defect on its first run: a comment ending in a full stop read as a qualified reference,
so `IShape.` was rewritten while `Helpers,` and `Widget,` beside it were not. Only code counts
now — strings end at their closing quote, doubled quotes being an escape, and comments run from
the first apostrophe outside a string.

Note `Circle` is not available as a module name; the Excel object library owns it and VBA refuses
with a bare HRESULT. The fixture uses `RoundShape`, and the script names the refused name rather
than passing the number along.

## 5. Working notes

- Publish Debug after every change: `dotnet publish src\Xlide.Vbe.Shim\Xlide.Vbe.Shim.csproj -c
  Debug -r win-x64`, with `DOTNET_ROOT` at `%LOCALAPPDATA%\Microsoft\dotnet` and
  `%ProgramFiles(x86)%\Microsoft Visual Studio\Installer` on PATH.
- Engine changes need `npm run package`, not `npm run build`.
- Excel holds both the shim DLL and the engine executable; close it first.
- `tools\verify.ps1 -Quick` before committing. Nine steps.
- The debug api discovery file is `%LOCALAPPDATA%\xlide_vbide\debug-api-<pid>.json`; routes
  `/doctor /state /stats /module /eval`. `/stats` now reports `windowEvents`, `refreshPasses`,
  `refreshTotalMs`, `refreshMaxMs`, `overlayMs`, `browserMs` and `browserCalls`.
- Those millisecond figures come from `Environment.TickCount64`, ~15.6 ms granularity. The counts
  are exact; the times are indicative. Move them to `Stopwatch.GetTimestamp()` before anyone
  optimises against them.
