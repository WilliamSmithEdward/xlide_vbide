## 1. The one that mattered: Excel was being killed by this product

Four crashes on 2026-08-07 wearing three different faces. Two heap corruptions blamed on `ntdll`
at the same fault offset, one access violation blamed on `VBE7.DLL`, one blamed on
`Xlide.Vbe.Shim.dll`. Three libraries, three exception codes, hours apart, each in the middle of
something ordinary. They read as three unrelated instabilities and were nearly filed as "the host
is flaky today".

The fourth carried a managed stack, and it was the whole answer:

```
Marshal.Release -> FreeThreadedStrategy.Release -> ComObject.Finalize -> DrainQueue
```

`GetOrCreateObjectForComInstance` builds a wrapper that takes its OWN reference on top of the one
the caller holds, and a `UniqueInstance` wrapper is never cached, so nothing else will ever give
it back. `DispatchObject.Dispose` released only the caller's. The wrapper then held a live editor
object until the collector reached it, and the finalizer thread released it. The editor's objects
are apartment-threaded, so that release is an access violation the runtime cannot throw: it
FailFasts, and Excel goes with it. It also corrupts COM's own bookkeeping, which is why the same
defect was reported against `ntdll` and `VBE7.DLL` as readily as against us.

`ComHandle.Dispose` had always done it correctly and its comment says why. The missing line was in
the type that does nearly all the control-plane work, absent since it was written.

**Scale, with the defect restored on purpose:** one `project()` call leaked 441 wrappers, reading
the native panes 156, moving the caret 29. A short probe run took the live count from 13 to 8,734.

### And a second one, which the instrument built for the first could not see

Excel died again with the identical stack while the counter read a balanced 13. Both facts were
true, and together they are precise: a wrapper was reaching the finalizer that this product never
took. It was this, at the bottom of the variant-to-text conversion:

```csharp
_ => value.As<object>()?.ToString(),
```

For a variant holding `VT_DISPATCH` or `VT_UNKNOWN` that asks the runtime for a wrapper over the
interface. Not taken through `ComRuntime`, so uncounted; never disposed, so finalized. One per
property read of an object-valued member.

**What found it was the crash reporter, not the leak counter.** Lessons 40 has the general form:
an instrument measures what it was pointed at, so keep one watching OUTCOMES beside the one
watching MECHANISM.

### VBA will not store a tab

Measured on both write paths and mid-line: the editor expands every tab to the next four-column
stop. So "indent with tabs" could never be reflected in the module, and **the setting was removed
on the developer's call**. Indentation is spaces at the chosen width; Backspace in leading
whitespace takes back a whole level.

## 3. What the api gained

| | |
| --- | --- |
| `projects` | EVERY open workbook. `project` answers about one, so with two open nothing could discover the other's name from the host. `projectHolding(module)` finds the workbook a module is in. |

| `immediate` | Answers WHAT THE LINE CAME TO rather than that an evaluation was asked for. Without `text` it reads the window. |

| `whyDidItDie()` | Asks the Windows event log the moment a call fails, and prints the faulting module and the managed stack. Every failed call appends it. |

## 4. The gate, and how it is meant to be used

**No memory leaks is release-blocking**, on the developer's instruction. `com-leak.mjs` is a gate
step: 36 rows over every read route, the assert predicates, and the state-changing routes each
paired with its own undo. Proven both ways, which is the only thing that makes it worth having.

`format-positions`, `three-copies` and `immediate-watch` are gate steps too. They existed, passed,
and nothing ran them.

> **Day to day, drive the api directly and do not write a script** (the developer, 2026-08-07).
> The client is a CLI with a verb per route. A full suite pass is about two and a half minutes plus
> a restart, and paying that for a one-line question is what makes a loop feel slow. Write a suite
> when the check is a REGRESSION worth keeping; run the full pass before a commit touching the
> editor surface, COM or the engine, and when a crash or leak is suspected.

Timings after halving the sweep: com-leak 63s (was 123s), format-positions 19s, three-copies 29s,
immediate-watch 21s. The trim was re-falsified at the new timings rather than assumed.

**Always launch with `-Fresh`.** Excel reuses one process, so launching while an older instance is
shutting down attaches to that one and dies on "Could not reach Excel NNNN through its window".

## 5. Performance: measured, and nothing changed

The live-analysis debounce is 350ms under 200,000 characters and 1500ms over. The threshold looks
wrong and the measurement says why: the 11k-line module and the 4.5k-line module cost the analyzer
the SAME, because it scales sub-linearly.

| module | size | analyzer | debounce | keystroke to squiggle |
| --- | --- | --- | --- | --- |
| Large | 4,502 lines, 101k chars | median 27ms, p95 248ms | 350ms | 610ms |
| Huge | 11,252 lines, 256k chars | median 24ms, p95 239ms | 1500ms | 966ms |

End to end both are under a second, so lowering the constant would raise the analyzer's duty cycle
for a sub-second gain. Recorded so the next person tempted by it does not have to re-measure.

Otherwise healthy: `pagecall` 0.38ms median, page-side typing 3.2ms, 25 characters through the
keyboard pipeline 90ms, completions 1ms in the analyzer, hover 22ms, wrappers live 13.

## 7. What this session was actually about

Almost every defect above was found by an instrument, and almost every instrument was wrong at
least once first. That is the thread worth carrying, and it is why the lessons entries spend more
words on the failed instruments than on the fixes.

- A `gc` route built to make the crash deterministic reported completely clean with 8,734 leaked
  wrappers pending. Deleted.
- The first leak counter incremented beside the disposal rather than by it, and read balanced on a
  build with the disposal deleted. Rewritten so the two cannot be separated.
- A per-row handle check fired on Excel's own churn and picked different rows each run. Moved to a
  whole-sweep judgement where the signal beats the noise.
- The leak sweep divided by the wrong denominator and announced round counts that had not happened.
- The finding-retires check took three attempts to bite: an open module clears its own findings, a
  partially-cleaned module leaves another module complaining, and only a wholly clean project
  reaches the state the bug needs.
- A one-line probe of mine reported `bench tabswitch` as 0ms. The door was honest and errored; the
  probe swallowed it with `.catch(() => ({}))`.

**An instrument is not proven by passing on a good build. It is proven by failing on a bad one.**
Every check that now guards this repo has been shown failing on a build broken on purpose, and the
ones that could not be are named as such in their own files.
